compile vs interpreted:
- for efficiency reasons, it's recommend that you compile code for production
- bedrock supports jitting, so you can just run it like an interpreted languages if you're prototyping (and it'll still be ~fast)
    - jitting is less extreme, so we make no guarantees that there is no runtime error missed (depends on how good the jit ends up being)

typing:
- recommended to statically type so that jit has an easier time, e.g. x: int = 5
    - note we do this colon notation so it's consistent with function parameter typing
- dynamic typing is supported when prototyping, exactly like how it is in python. depends on how good jit is (funny reference)

Functional stuff for the functional nerds:

functions are first-class citizens

square x = x * x
fn foo square x {
    square x # parentheses are optional, since it's obvious the scope ends upon newline or semicolon
}

fn bar square y: list {
    map square y
}

The only reason why we'd need immutability would be for shared/referenced memory. More to come on the fate of mut in bdr.

Arrays:

There are no arrays! We call them tensors to keep full generality.

x = [[1,2,3], [4,5,6]]

There are also no such thing as tuples. Again, everything is a tensor. If you want the contents, unpack them:

first_three, second_three = x
one, two, three = first_three
four, five, six = second_three

in transitively,
one, two, three, four, five, six = x # is this even possible to specify
